# 软件接口总览表 · 生成与对比

本 skill 约束「软件接口总览表生成与对比」任务的执行。核心原则只有一条：

> **所有专业结论由确定性工具算出，模型只负责理解意图、选对工具、解释结果。**
> 模型无权改写任何计算结果，无权在工具之外推断链路关系。

## 任务边界

本 skill 只做两件事，二者相互独立：

| 能力 | 触发方式 | 说明 |
|---|---|---|
| 生成总览表 | `generate_overview` | 从标准接口包生成《软件组件接口收发总览表》 |
| 新旧对比 | `compare_overviews` | 拿新生成的总览表与已批准的旧版逐行对比 |

用户只要"第一次生成"时，不要顺带跑对比；只有明确给了旧版总览表（或工作记忆里有历史产物可串联）时才对比。意图判断规则：**用户消息出现对比/比较/差异/比对/compare/diff 等关键词时，必须走对比路径，找不到两份总览表就返回 needs_input 引导，绝不允许静默降级成重新生成**——这是踩过的坑：对比请求被误判为生成，旧表被覆盖，用户数据差点丢失。

## 输入要求（实际踩过的坑）

1. **路径引号**：用户从 Windows 资源管理器复制的路径自带英文双引号，直接拼路径会变成 `WinError 123`。入口处必须先剥掉两端引号（后端 `_clean_input_path` + 前端 `cleanPath` 双边界都做了，不要绕过它们）。
2. **文件类型校验**：对比任务只接受 Excel 总览表（.xlsx）。用户把接口包 zip 粘进对比输入框时，先尝试从工作记忆 `overview_history` 找最近生成的有效总览表作为候选自动替换；找不到就明确告知"当前找到 N 份总览表"，禁止把 zip 直接传给 openpyxl 导致堆栈报错。
3. **耗时预期**：大接口包（60+ 模块、1.5 万+ 行）生成约 10~40 秒，属正常。执行中要发进度事件，别让用户以为卡死。
4. **零输入智能补齐**：路径输入框允许为空，按「输入框 > 消息文本提取 > 工作记忆串联」三级链自动补齐；消息文本提取只接受真实存在的本地路径。

## 操作路由

每个工作项必须带显式 `parameters.operation`，禁止执行时从模糊标题猜操作：

| operation | MCP 工具 | 什么时候用 |
|---|---|---|
| `analyze_package` | `fusa_interface_analyze_package` | 只想看包结构、词典、映射配置，不生成 |
| `generate_overview` | `fusa_interface_generate_overview` | 正式生成总览表，默认 `fast` 引擎 |
| `compare_overviews` | `fusa_interface_compare_overviews` | 聚焦的新旧总览表对比 |
| `compare_configs` | `fusa_interface_compare_configs` | 只对比当前配置与基线配置 |
| `inspect_overview` | `fusa_interface_inspect_overview` | 总览表已存在，只审链路覆盖率 |

`analyze_package` 是审计工具，**不能替代** `generate_overview`：包里没有已批准总览表时，包分析的原生匹配结果只能标注"基础结构化匹配"，不得宣称与 legacy 规则完全等价。

## 生成不变量（来自 VBA 宏逆向，逐条硬约束）

快速引擎复刻自 `UpdateXLSMFileNameColumn20251212` 和 `Process_Single_File_Inner202604201900`，以下规则在工具代码里实现，模型必须知道它们的存在，以便向用户解释结果：

- 只有命中 `外部组件映射配置` 中启用的排除规则键的映射，才参与 AA/AB 跨应用链路计算。
- 判断链路组时忽略适配器模块：`ACF-ACFService`、`FM-FMService`、`MCF-MCFService`、`RCF-RCFService`、`FMB-FMBService`。
- 有效链路组 = 恰好一个非适配器 `Output` + 至少一个非适配器 `Input`。
- 参与计算但无效的组，AA 和 AB 两列都必须写「链路流信号流缺失」；不参与计算的行保持空白。
- 独立校验失败 = 阻断自动交付，**禁止用模型生成的值修补工作簿**。

## 对比不变量

- 第一本工作簿是新版本，第二本是旧版本，别弄反。
- 必须按业务键列对比（工具内置的业务键配置），禁止只按 Excel 行号对齐。
- 新增行、删除行、变更单元格、未变行四类结果分开报告；重复业务键要单独提示，不许静默挑一条当权威。
- 重复键导致配对歧义时参考 `content_multiset_parity`（剔除序号列的多重集视图），但它只能辅助判断，**不能用来吞掉真实的新增/删除行**。
- 疑似重命名只是 review 候选，永远不会被自动接受。

## 人工确认门（一票否决）

以下情况必须停在人工确认，工具和模型都无权跳过：

- 每一份交付文件
- 检测到的每一处总览表变更
- 重复业务键、疑似重命名
- 未消解的映射、缺失的跨应用链路、被删除的配置行

确认后写入审计记录；用户对结果有异议时直接在对话里补充描述即可重新发起。判定标准细节见 [references/review-contract.md](references/review-contract.md)。

## 证据与留痕

每次执行必须保留完整证据链，缺一项即视为交付不合规：

- 输入 manifest（源相对路径 + SHA-256）
- 生成的总览表 + staged 的 Unit 配置快照
- 引擎日志 + 独立校验证据 + 机器可读报告
- 对比任务额外保留：对比工作簿、JSON 报告、行级 JSONL 证据、输入/输出 SHA-256

快速引擎结果与已批准的 legacy 基线不一致时，停在人工门；已知修正过的行不能为了凑旧行数被悄悄丢弃。

## 环境红线

- 源 zip / 源目录只读，一律在 staged 副本上执行。
- 模块 XLSM、PIE Matrix、Unit2ComponentConfig 是**版本化项目输入**，不是 RAG 知识，不要混入知识检索。
- legacy 引擎只能作为兼容性 oracle 在隔离副本上调用，永远不要让模型编写或执行任意工作簿宏。
