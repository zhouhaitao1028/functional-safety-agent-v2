# HARA 分析 Skill

> 本 skill 由 HARA 一线工程师维护，Agent harness 在执行 HARA 环节任务前按本声明检索材料并注入子 Agent。

## 用到的指南模板

- `gd-hara-analysis` HARA 分析指南（主指南，分析步骤按第 2 节顺序执行）
- `tp-hara-worksheet` HARA 评估表模板（产出物格式，ASIL 列禁止人工填写）
- `tp-function-model` 功能清单模板（输入物，用于确认功能边界与场景枚举是否齐全）

## 易错点

- 把「功能不执行」和「功能误执行」合并为一条危害事件——必须按失效模式拆成两条，S/E/C 分别评估。
- E 等级没有暴露依据。高速巡航 E4 可以接受，但「暴雨夜路」这类 E2 以下场景必须附气象/工况统计来源。
- C 等级忽略驾驶员辅助手段：有声光报警 + ≥2s 反应窗口的，C 最多给到 2。
- 危害事件未绑定运行场景——场景缺失会导致下游安全目标覆盖不全，评审必打回。
- 人工预填 ASIL 等级：ASIL 一律由规则程序按 S/E/C 矩阵计算，表格里人工写了也会被确定性校验覆盖。
- 同一失效在不同车速区间严重度不同时，必须按场景假设拆行（如 60km/h 以下 S2，以上 S3）。

## 跳转参考

- 当功能的运行场景涉及新市场/新法规（如出口车型）→ 参考 `gd-function-definition` 第 2.3 节，先补全场景再评估 E。
- 当危害事件涉及制动/转向等既有安全功能 → 参考 `gd-safety-goal`，检查是否已有安全目标覆盖本场景，避免重复建模。
- 当 S/E/C 争论超过一轮评审未决 → 参考 `gd-hara-analysis` 第 3 节易错点逐条对照，仍不能定则按保守取值并记录分歧。
