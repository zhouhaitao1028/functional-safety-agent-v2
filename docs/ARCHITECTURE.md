# 架构决策：Manager 动态路由业务 Agent

## 1. 产品定位

V2 不是另一个通用 Codex，而是功能安全工程的业务能力、数据契约、知识、确定性服务和人工审批平台。模型供应商只是可替换基础设施。

## 2. 调度模型

Manager 接收用户目标和输入资料元数据，读取 Agent Registry 后生成 `workplan.json`。工作计划必须明确：

- 选用哪个业务 Agent；
- 每项工作消费和产生的数据类型；
- 工作项依赖关系；
- 输出文件名；
- 人工确认点。

后端对工作计划做确定性验证：Agent 是否存在、输入输出类型是否匹配、引用是否有来源、DAG 是否成环、依赖是否完整、是否试图关闭强制人工门禁。计划通过人工批准后才能执行。

Manager 的模型运行入口会强制它先调用 `agent_registry.list`，并对每个带路径的输入调用只读 `source.inspect`。模型不得改变调用方给定的输入 ID、类型和路径；生成结果还要依次通过 Workplan Schema 和 Agent 能力契约。工具调用、模型信息和原始请求写入工作计划 provenance。

`workflow-run` 从 DAG 中领取当前满足依赖的业务 Agent。默认并发度为 1；设置 `--max-parallel N` 后，会同时执行最多 N 个互不依赖的就绪节点。每个交付物仍独立停在人工门前；下游节点只接受 `approved` 状态，不会把“已经生成但未批准”误当成完成。

固定 recipe 只用于组织已经稳定、重复率高的标准任务。用户可以选择 recipe，也可以让 Manager 生成更短、分支更多或可并行的计划。

## 3. Agent 边界

### Manager Agent

只负责任务理解、能力选择和计划生成。它不能直接批准计划，也不能直接产出 HARA、FTA、FSR 等结论。

### Engineer Agent

每个 Engineer 拥有一种业务能力，通过配置声明 `consumes`、`produces`、Schema、知识范围、确定性校验和 API。它只能生成候选结构化数据，不能伪造审批。

### Validator

能够用代码完成的工作不调用模型，例如 ASIL 查表、FTA 最小割集、ID 唯一性、追溯完整性、Schema 和模板字段校验。

### Action Agent

只有需要读取复杂文件、生成 Word/Excel 或调用受控工具时才启用。`document_engineer` 读取已批准结构化数据和公司模板，不能修改上游业务结论。

## 4. 信任边界

```text
模型输出（不可信候选）
        ↓
JSON Schema
        ↓
确定性计算与一致性校验
        ↓
候选产物
        ↓
人工审批（绑定 SHA-256）
        ↓
下游 Agent 可消费的已批准产物
```

模型可以建议，程序可以验证，人才能批准。

## 5. 并行策略

并行由工作计划 DAG 决定，而不是靠多个 Agent 争抢同一文件。没有依赖关系的工作项可以并行，例如多个独立功能、多个危害事件或多个安全目标。Worker 只产生隔离 JSON，后端统一校验和合并，不允许多个 Worker 同时编辑同一 Word/Excel。

本地 Worker Pool 使用 SQLite WAL 保存工作项状态、依赖、尝试次数和执行事件。领取工作采用原子事务；每个领取记录包含 worker ID、租约 token、心跳、输入指纹和幂等键。提交结果必须携带仍有效的租约 token，并用 compare-and-swap 更新状态；租约过期后任务进入重试或最终失败，旧 Worker 的迟到提交会被拒绝。工作计划同时禁止两个节点声明相同的输出文件名。

这个实现提供的是单机线程池上的 at-least-once 执行和幂等可见提交，不宣称外部模型调用 exactly-once。生产环境如果扩展到多机，还需要分布式队列、对象存储、跨主机锁、模型供应商级并发配额和统一可观测性。

## 6. API 与密钥

`config/agents/*.json` 是每个 Agent 的独立配置。它只保存环境变量名和非敏感推理参数。真实密钥来自环境变量或后续密钥管理服务。Registry 会拒绝配置文件中的 `api_key`、`token`、`access_token` 或 `secret` 明文字段。

不同 Agent 可以使用不同模型：Manager 可使用强推理模型，普通提取 Agent 可使用更快模型，确定性 Validator 不接模型。

业务 Agent 通过有界工具循环运行：模型只能调用其配置声明的只读工具；后端校验工具名和参数、限制知识标签与草稿权限，并把工具结果作为 `tool` 消息返回模型。需要业务知识的 Agent 如果未调用知识检索就直接提交结论，运行时会拒绝该结果。工具调用记录和证据 ID 会写入产物 `provenance`。

## 7. 知识与模板

知识库不属于任何 Agent。旧项目中的 `01_指导手册` 是规则来源，`02_模板` 是模板资产；两者保留原始文件，并被解析为带段落、表格行或工作表定位的证据块。

知识服务包含四个接口：混合 RAG 返回证据包，关系图回答跨文档与影响问题，Wiki 供人浏览审核，原始资产定位供 `document_engineer` 精确使用模板。Skill 只规定 Agent 如何选择和使用这些接口，不承载原始知识内容。

当前图增强检索会从命中的证据文档扩展指导手册—模板—业务域关系。它是 GraphRAG 的本地基础版，不包含社区发现、全图摘要等重型离线算法。

项目输入、过程产物和输出物默认属于具体项目，不能未经脱敏和审批自动进入全局知识库。
