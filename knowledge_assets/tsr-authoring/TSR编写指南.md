# TSR 编写指南

> 对应 ISO 26262-4 第 6 章。TSR 把安全目标细化到系统层面，是 FSR 的唯一上级；TSR 必须逐条追溯到安全目标。

## 1. 输入

- 已批准的安全目标清单
- 系统架构草案（用于安全机制分配）

## 2. 编写要求

1. **逐条追溯**：每条 TSR 填写 `parent_sg_ids`；一条 TSR 只服务一条安全目标，需要覆盖多条时拆分。
2. **安全机制化**：TSR 描述安全机制（探测、抑制、降级、告警），而不是重复安全目标。
3. **ASIL 继承**：TSR ASIL = 其安全目标 ASIL；分解（ASIL × (B)D）必须注明分解方案与独立性依据。
4. **可验证性**：每条 TSR 给出验证方法候选（测试/分析/评审）。

## 3. 易错点（评审重点）

- 多条安全目标被同一条 TSR 隐式覆盖，追溯链断裂
- 把功能需求当 TSR 录入（无 parent_sg_ids）
- ASIL 分解未附独立性论证
- ID 重复或使用已废弃编号

## 4. 产出

按《TSR 需求清单模板》（`tp-tsr-list`）输出，经校验程序检查结构、ASIL、来源与 ID 唯一性后进入 FSR 环节（`fsr-authoring`）。
