# FSR 导出指南

> 对应 ISO 26262-6 第 6 章。FSR 从已批准 TSR 导出到软件层面，保持上级追溯；**无法确定的字段一律写 TBD，禁止臆造**。

## 1. 输入

- 已批准的 TSR 清单（`tp-tsr-list` 产出）
- 软件接口总览表（`interface_overview`，由软件接口追溯环节产出）
- 软件架构草案

## 2. 编写要求

1. **逐条追溯**：每条 FSR 填写 `parent_tsr_ids`；FSR ASIL 继承 TSR。
2. **软件可实施**：FSR 描述软件可实现的机制（监控函数、安全状态转换、去抖策略）。
3. **时间约束显式化**：把 TSR 的 FTTI 分解为软件周期约束（采样周期、响应 deadline）。
4. **分配对象**：标注 FSR 分配到的软件组件候选；分配到多个组件时须满足 ASIL 分解独立性。

## 3. 易错点（评审重点）

- TBD 未按规范标注，混入臆造值（合规红线）
- 接口相关 FSR 未引用接口总览表的信号 ID，导致信号变更时影响分析遗漏
- 时间约束照抄 FTTI 未做软件周期分解
- 一条 FSR 覆盖多条 TSR 但未列 parent_tsr_ids 映射

## 4. 产出与追溯

按《FSR 清单模板》（`tp-fsr-list`）输出。FSR ↔ TSR 双向追溯；下游进入软件架构分配环节（`software-architecture`）。接口信号变更时，依据 FSR 引用的信号 ID 做变更影响分析。
