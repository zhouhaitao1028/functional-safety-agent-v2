# HARA 分析指南

> 对应 ISO 26262-3 第 6 章。HARA 的输出是安全目标的唯一来源；S/E/C 给候选与依据，**ASIL 等级一律由确定性规则程序计算**，禁止人工查表填等级。

## 1. 输入

- 已批准的功能清单（`tp-function-model` 产出）
- 运行场景说明

## 2. 分析步骤

1. **识别功能失效**：对每个功能枚举失效模式（不执行、误执行、执行不完整、执行延迟、反向执行）。
2. **定义危害事件**：功能失效 × 运行场景 → 危害事件，每条给出场景假设（车速、道路、周边目标）。
3. **S/E/C 候选评估**：
   - S（严重度）：0–3，按伤害后果给出候选与**逐条依据**；
   - E（暴露率）：0–4，按场景暴露时间/概率给出候选与依据；
   - C（可控性）：0–3，按驾驶员可控性给出候选与依据。
4. **ASIL 确定**：由规则程序按 S/E/C 查矩阵得出；ASIL 等级与安全目标在评审前为候选状态。
5. **安全目标方向**：为每个 ASIL≥A 的危害事件给出安全目标方向性描述（安全状态是什么）。

## 3. 易错点（评审重点）

- 把「系统不响应」与「系统误动作」合并成一条危害事件——必须分开
- E 等级凭感觉给，没有暴露概率依据
- C 等级忽略驾驶员辅助手段（报警、余留操纵）
- 危害事件没有绑定运行场景，导致安全目标覆盖不全
- 人工预填 ASIL 等级（必须由程序计算）

## 4. 产出与追溯

按《HARA 评估表模板》（`tp-hara-worksheet`）输出。危害事件与功能（FUN-xxx）双向追溯；ASIL≥A 的条目进入安全目标环节（`safety-goal`）。
