# 安全目标编写指南

> 对应 ISO 26262-3 第 6.4.2 节及 ISO 26262-8 第 6 章。安全目标从已确认的 HARA 结果导出，是 TSR 的唯一上级依据；安全目标变更必须走变更影响分析。

## 1. 输入

- 已评审确认的 HARA 评估表（`tp-hara-worksheet` 产出）
- 安全状态定义资料（整车层面）

## 2. 编写要求

1. **一一对应**：每条 ASIL≥A 的危害事件至少对应一条安全目标；同一安全目标可覆盖多个危害事件，但必须显式列出覆盖关系。
2. **安全状态可执行**：安全目标描述的是「系统应处于/达到的安全状态」，不是「禁止发生事故」这类不可实现表述。
3. **继承 ASIL**：安全目标 ASIL 继承对应危害事件的 ASIL，不得升降。
4. **容错时间**：给出 FTTI（故障容忍时间间隔）候选，注明依据。

## 3. 易错点（评审重点）

- 安全目标写成功能需求（描述怎么做到）而非安全状态（描述要做到什么）
- 一条安全目标对应多条危害事件但未列出映射，导致变更影响分析遗漏
- 漏写 ASIL 或与 HARA 不一致

## 4. 产出与追溯

安全目标清单：SG-xxx ↔ HE-xxx 双向追溯。下游进入 TSR 环节（`tsr-authoring`）。
