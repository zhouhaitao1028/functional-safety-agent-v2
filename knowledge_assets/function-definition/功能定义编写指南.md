# 功能定义编写指南

> 对应 ISO 26262-3 第 5 章「需求定义与特性描述」。本指南说明如何把项目资料整理成可用于 HARA 分析的功能定义。

## 1. 输入材料

- 系统需求文档 / 整车功能规范
- 上一版本的功能清单（如有）
- 运行场景说明（路况、车速区间、地域、使用人群）

## 2. 编写要求

1. **功能边界**：明确功能覆盖的执行器与信号范围，写清「本功能不负责什么」。
2. **功能状态**：列出状态的迁移条件（如 待机 → 激活 → 降级 → 退出）。
3. **运行场景**：必须覆盖全部相关运行模式；遗漏场景是 HARA 危害遗漏的直接原因。
4. **接口清单**：给出功能与外部系统的信号收发关系，标注信号来源系统。

## 3. 易错点（评审重点）

- 功能边界写成系统架构，混入实现细节
- 运行场景只写典型场景，漏掉泊车、高速、隧道等特殊场景
- 功能状态迁移条件含糊（"必要时""适当时候"）

## 4. 产出

按《功能清单模板》（`tp-function-model`）输出功能清单，经评审后作为 HARA 分析（`hara-analysis` 环节）的输入。
